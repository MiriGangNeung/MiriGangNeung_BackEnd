# 장소 이미지 CDN 호환 저장 구조 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 관광공사 원본 이미지의 반복 직접 다운로드를 없애고, 카드용 썸네일·합성용 원본을 저장소 기반 URL로 제공한다.

**Architecture:** 백엔드는 동기화 시 source URL을 `ImageAssetCacheService`로 한 번 다운로드하고 `PlaceImageStorage` 구현체에 원본과 썸네일을 저장한다. DB는 source URL과 storage key/메타데이터를 보존하며, `/media/images/{key}`는 장기 캐시 헤더를 붙여 파일을 스트리밍한다. 프론트는 카드에서 썸네일 URL을 사용하고 `originalImageUrls`를 같은 이미지 순서로 보존한다.

**Tech Stack:** Java 17, Spring Boot 4, Spring Data JPA, Spring MVC, Java `HttpClient`, Java `ImageIO`, JUnit 5, AssertJ, Mockito, React 18, TypeScript, Vitest.

**Spec:** `docs/superpowers/specs/2026-08-24-image-cdn-design.md`

## Global Constraints

- Type1 이미지와 기존 장소 매칭 정책만 사용한다.
- Redis에는 장소 JSON만 저장하고 이미지 binary는 저장하지 않는다.
- 관광공사 호출은 명시적인 동기화 흐름에서만 발생시킨다.
- Base64 이미지를 API JSON에 넣지 않는다.
- 새 외부 object storage/CDN dependency를 추가하지 않는다.
- 캐시 파일이 없는 기존 데이터는 기존 원본 URL로 동작해야 한다.
- 수정 전후 `bash gradlew test`, 프론트 `npm test -- --run`, `npm run lint`, `npm run build`를 실행한다.
