# 코스 장소 검색·세부 선호 추천 설계

> 상태: 사용자 승인 설계
>
> 작성일: 2026-08-28

## 목표

코스 결과의 장소 추가 흐름을 카테고리 중심으로 재구성한다. 사용자는 카페·음식점·문화시설·관광명소 중 하나를 먼저 고른 뒤, 해당 카테고리 안에서 주변 추천·강릉 전체 검색·강릉 대표 모드를 선택한다. 주변 추천은 코스 생성 때 선택한 여행 타입과 세부 선호, 동행 유형을 이용해 설명 가능한 점수를 계산한다.

LLM, 리뷰 원문, 별점, 별도 인기 API는 사용하지 않는다. Kakao Local 응답의 장소명·카테고리명·주소·도로명 주소와 기존 코스 선호값만 사용한다.

## 확정 결정

### 장소 추가 패널

1차 선택은 다음 네 카테고리 탭이다.

- 카페
- 음식점
- 문화시설
- 관광명소

선택한 카테고리 안에 2차 segmented control로 다음 세 모드를 둔다.

- 주변 추천
- 강릉 전체 검색
- 강릉 대표

예를 들어 음식점을 선택하면 음식점 패널 안에 세 모드가 보인다. 카테고리와 모드를 동일한 레벨의 일곱 개 버튼으로 펼치지 않는다.

강릉 전체 검색은 패널을 열었을 때 Kakao API를 호출하지 않는다. 검색 입력과 검색 버튼만 먼저 보여주고, 사용자가 키워드를 제출했을 때 선택된 카테고리의 Kakao 키워드 검색 API를 호출한다. 빈 상태에서 45개를 미리 노출하지 않는다.

강릉 대표 탭은 기존 결정대로 이번 범위에서는 준비 중 상태로 유지한다. 클릭해도 네트워크 요청을 발생시키지 않는다. 대표 장소의 조사·순위·별점·리뷰 수는 별도 기능으로 분리한다.

### 여행 타입과 세부 선호

기존 액티비티 타입은 새 UI에서 제거한다. 기존 DB에 저장된 active 값은 하위 호환을 위해 읽을 수 있지만 신규 선택지와 추천 점수에는 사용하지 않는다.

여행 타입은 기존처럼 최소 1개, 최대 2개를 선택한다. 각 선택 타입은 최대 1개의 세부 선호를 선택한다. 세부 선호를 고르지 않으면 해당 타입의 넓은 기본 키워드 집합을 사용한다.

식도락:

- 한식
- 중식
- 일식
- 양식

휴식:

- 커피·로스터리
- 디저트·베이커리

문화·예술:

- 미술관·갤러리
- 전시관·전시
- 박물관·기념관

자연·산책은 세부 선택 없이 관광명소 카테고리에 일반화된 키워드 집합을 적용한다.

선택값은 UI 문구가 아니라 안정적인 식별자 목록으로 코스 생성 request·DB·response에 함께 보존한다.

    detailTypes: ["food:chinese", "rest:coffee"]

기존 코스에 detailTypes가 없으면 대분류 기본 키워드를 사용한다.

### 카테고리와 여행 타입 연결

주변 추천에서 현재 카테고리와 관련된 여행 타입만 주된 선호 점수에 반영한다.

- restaurant → food
- cafe → rest
- culture → culture
- attraction → nature

두 타입을 선택했더라도 후보 카테고리와 맞지 않는 타입이 점수를 희석하지 않도록 평균을 사용하지 않는다. 현재 카테고리에 적용 가능한 프로필 중 가장 높은 적합도만 사용한다. 적용 가능한 프로필이 없으면 거리·동행·정보 완성도만으로 정렬한다.

### 추천 점수

점수는 0~100 범위로 반환한다.

| 항목 | 최대 점수 | 역할 |
| --- | ---: | --- |
| 여행 타입·세부 키워드 적합도 | 60 | 가장 큰 영향. 중식 선택 시 양식보다 중식을 우선 |
| 거리 | 20 | 선택 관광지에서 가까울수록 가점 |
| 동행 유형 | 10 | 보조 신호로만 사용 |
| 장소 정보 완성도 | 10 | 주소·전화·URL·좌표 등의 존재 여부 |
| 카페 프랜차이즈 감점 | -8 | 주변 추천의 추천순에서만 적용 |

여행 타입 적합도는 다음 단계로 계산한다.

- 세부 키워드가 장소명·카테고리명·주소에 일치: 60점
- 대분류 기본 키워드가 일치: 40점
- 카테고리만 맞고 키워드가 없음: 10점
- 카테고리와 프로필이 맞지 않음: 0점

따라서 중식 키워드가 있는 2km 후보가 가까운 양식 후보보다 높은 점수를 가질 수 있다. 거리순 모드를 선택하면 이 점수와 무관하게 기존 거리 오름차순을 유지한다.

동행 점수는 기존 키워드를 사용하되 최대 10점으로 제한한다.

- 가족: 공원, 산책, 목장, 체험, 키즈, 가족, 박물관
- 커플: 바다, 해변, 전망, 감성, 사진, 데이트, 브런치, 경포, 안목
- 혼자: 조용, 산책, 서점, 공원, 독서, 전시
- 친구: 체험, 레저, 스포츠, 맛집, 사진, 게임, 술집

카페 주변 추천에서 장소명을 정규화한 뒤 메가MGC커피·메가커피·컴포즈커피·스타벅스·투썸플레이스가 포함되면 -8점을 적용한다. 프랜차이즈 감점은 사용자가 강릉 전체 검색으로 직접 검색한 결과에는 적용하지 않는다.

추천순은 점수 내림차순, 거리 오름차순, 장소명 순으로 정렬한다. 추천 이유는 최대 3개까지 반환하며 일치한 프로필을 설명하는 문구를 우선한다.

## 데이터 흐름

1. 프론트의 코스 옵션 화면에서 여행 타입과 세부 선호를 선택한다.
2. 코스 생성 request가 types, detailTypes, companion을 백엔드로 전달한다.
3. 백엔드는 코스에 세 값을 저장하고 Course response에도 반환한다.
4. 결과 화면의 장소 추가 패널은 response의 저장된 선호를 사용한다.
5. 주변 추천 요청은 선택 관광지 최대 3개 각각의 2km 후보를 Kakao에서 가져온다.
6. 백엔드는 현재 카테고리에 맞는 프로필로 점수를 계산하고 추천순 또는 거리순으로 반환한다.
7. 강릉 전체 검색은 선택 카테고리와 사용자가 제출한 keyword를 Kakao에 전달한다.
8. 사용자가 후보의 추가 버튼을 누른 경우에만 기존 외부 장소 snapshot으로 저장한다.

## API 계약 변경

코스 생성 request와 Course response에 detailTypes를 추가한다. 기존 코스는 빈 배열을 반환한다.

- nearby: category는 restaurant, cafe, culture, attraction 중 하나
- all: category는 선택된 동일 카테고리이며 keyword가 비어 있으면 Kakao를 호출하지 않도록 방어한다
- all 검색 결과는 거리·추천 점수를 반환하지 않는다
- nearby 추천순은 새 점수, nearby 거리순은 거리순을 사용한다
- 강릉 대표는 API 호출을 만들지 않는다

## 오류와 하위 호환

- detailTypes가 없거나 비어 있으면 대분류 기본 프로필로 계산한다.
- 허용되지 않은 detailTypes는 코스 생성 시 400으로 거부한다.
- 액티비티가 기존 코스에 저장되어 있어도 코스 조회는 성공해야 한다.
- all 검색의 공백 keyword는 Kakao 호출 없이 빈 결과로 처리한다. 프론트는 공백 상태에서 요청하지 않는다.
- Kakao에서 누락된 필드는 점수 계산에서 0점으로 처리하고 후보 자체는 좌표·ID·이름이 있으면 표시한다.
- 프랜차이즈 토큰은 후보를 제거하지 않고 추천순에서만 감점한다.

## 비범위

- 강릉 대표 장소의 실제 목록·리뷰 수·별점 조사
- Kakao 리뷰 원문 또는 별점 수집
- LLM 기반 의미 분석
- Kakao API 45개 제한을 우회하기 위한 대량 수집·DB 적재
- 여행 타입을 2개 초과로 선택하는 기능
- 자동으로 후보를 코스에 추가하는 기능

## 완료 기준

- 카테고리 4개가 1차 탭으로 보이고, 각 탭 안에 3개 모드가 정돈되어 보인다.
- 강릉 전체 검색 진입 시 Kakao 요청이 발생하지 않고 검색 제출 후에만 요청한다.
- 식도락·휴식·문화·자연 프로필과 액티비티 제거가 UI와 백엔드에 일관되게 반영된다.
- 중식처럼 세부 키워드가 일치하는 장소가 거리만 가까운 비일치 장소에 밀리지 않는다.
- 카페 프랜차이즈는 주변 추천순에서만 소폭 감점된다.
- 기존 코스와 기존 거리순 동작이 회귀하지 않는다.
- 백엔드 테스트, 프론트 테스트, 프론트 빌드가 통과한다.
