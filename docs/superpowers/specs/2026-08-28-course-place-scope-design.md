# 장소 추가 검색 범위 확장 설계

## 배경과 목표

현재 코스 결과의 장소 추가 패널은 선택한 관광지 주변 2km 안에서 카카오 장소를 검색한다. 이 구조만 유지하면 테라로사·동화가든처럼 유명하지만 선택한 관광지에서 먼 장소를 사용자가 찾거나 추가하기 어렵다.

이번 작업은 장소 추가 패널을 세 가지 모드로 나누고, 이번 범위에서는 주변 검색과 강릉 전체 검색을 구현한다. 강릉 대표 모드는 UI 자리만 마련하고 데이터·랭킹은 별도 조사 후 결정한다.

```text
장소 추가 패널
├── 주변 추천  ─ 선택 관광지 기준, 2km, 추천순/거리순
├── 강릉 전체  ─ 강릉 전역, 카테고리/검색어, 거리 미표시
└── 강릉 대표  ─ 이번 작업에서는 준비 중 버튼
```

## 확정된 제품 결정

- 상위 모드 버튼은 한 줄에 `[주변 추천] [강릉 전체] [강릉 대표]`를 둔다.
- 장소 카테고리는 한 줄에 `[카페] [음식점] [문화시설]`만 둔다. 관광명소 버튼은 장소 추가 UI에서 제거한다.
- `주변 추천`에서는 현재 코스의 외부 장소가 아닌 관광지 정거장만 기준으로 사용한다. `전체` 또는 최대 3개의 관광지 중 하나를 고를 수 있다.
- `주변 추천`의 추천순·거리순 정렬과 2km 반경은 유지한다.
- `강릉 전체`에서는 기준 관광지 선택 UI와 거리·가까운 관광지 문구를 숨긴다.
- `강릉 전체`는 선택한 카테고리에 대해 강릉 전역을 검색한다. 검색어가 비어 있으면 카테고리 목록을, 검색어가 있으면 강릉 전역의 키워드 결과를 제공한다.
- `강릉 전체` 결과도 카카오 장소 ID, 좌표, 카카오맵 URL을 사용해 지도 노드·미리보기·코스 추가를 지원한다.
- `강릉 대표`는 이번 작업에서 호출하지 않는다. 버튼은 비활성화하고 `준비 중` 상태를 표시한다.
- 장소를 선택했다고 자동으로 코스에 넣지 않는다. 기존처럼 사용자가 추가 동작을 수행할 때만 코스 스냅샷을 저장한다.
- `강릉 전체`에서는 API가 반환한 거리값을 카드에 표시하지 않는다. 응답 내부의 거리는 선택적인 값으로 다룬다.
- 카카오가 제공하는 페이지 단위 결과를 사용하며, 한 번에 전 페이지를 호출하지 않는다. 다음 페이지를 요청하는 방식으로 초기 로딩을 가볍게 유지한다.

## 브랜치와 기준 코드

추천순·거리순과 코스 선호값 저장은 현재 `feat/issue-13-place-recommendation` 브랜치에만 있다. 따라서 새 작업은 다음 기존 브랜치에서 각각 파생한다.

- 프론트: `feat/course-place-scope` ← `feat/issue-13-place-recommendation`
- 백엔드: `feat/course-place-scope` ← `feat/issue-13-place-recommendation`

최신 `main`/`develop`에서 바로 파생하면 기존 추천순·거리순 구현이 빠지므로 사용하지 않는다.

## 시스템 구조

### 프론트엔드

- `CourseResultPage`가 `nearbyScope`, `nearbyCategory`, `nearbyStopId`, `nearbySort`, `nearbyKeyword`, `nearbyPage` 상태를 관리한다.
- `CourseResult`는 상위 모드 탭, 카테고리 탭, 주변 기준 관광지 선택, 주변 정렬, 전체 검색어 입력을 모드에 따라 표시한다.
- `useCoursePlacesQuery`의 query key에 범위·카테고리·기준 관광지·정렬·검색어·페이지를 포함해 서로 다른 결과가 섞이지 않게 한다.
- `NearbyPlaceCard`는 `nearby` 범위에서만 거리와 기준 관광지를 표시한다. `all` 범위에서는 장소명·주소·카테고리·카카오맵 리뷰 보기만 표시한다.
- `CourseMap`은 현재 코스 정거장과 별도로 검색 결과 노드를 받을 수 있게 한다. 전체 검색 결과 노드를 클릭하면 기존 장소 미리보기 흐름을 사용한다.
- 기존 외부 장소 추가 요청 payload는 유지한다.

### 백엔드

- `CourseController`의 기존 `/nearby-places` 경로를 확장해 범위·검색어·페이지를 받는다.
- `CoursePlaceService`는 `nearby`와 `all` 검색 흐름을 분리한다.
- `KakaoLocalClient`는 기존 좌표 반경 카테고리 조회와 별도로 사각형(`rect`) 기반 카테고리·키워드 조회를 지원한다.
- `nearby`는 기존 코스 관광지 좌표와 `radiusMeters`를 사용한다.
- `all`은 강릉 서비스 영역의 고정 bounding box를 사용한다. 좌표는 코드에 흩어놓지 않고 `KakaoLocalProperties` 또는 장소 검색 설정으로 관리한다.
- 검색 결과는 카카오 장소 ID로 중복 제거한다. 기존 코스의 관광지명과 동일한 장소를 추가 후보에서 제외하는 규칙도 유지한다.
- 카카오 응답의 주소·좌표·장소 URL을 그대로 정규화해 반환한다. 별점·리뷰 수·인기 점수는 추가하지 않는다.

## API 계약

### 장소 검색

기존 호출과 호환되도록 `scope` 기본값은 `nearby`로 둔다.

```http
GET /api/v1/courses/{courseId}/nearby-places
  ?scope=nearby
  &category=cafe|restaurant|culture
  &stopId=all|{tourismStopId}
  &sort=recommended|distance
  &page=0
  &size=15
```

```http
GET /api/v1/courses/{courseId}/nearby-places
  ?scope=all
  &category=cafe|restaurant|culture
  &keyword={optional}
  &page=0
  &size=15
```

`scope=nearby`에서는 `stopId`와 `sort`를 사용하고, `scope=all`에서는 `stopId`와 `sort`를 무시하거나 기본값으로 처리한다. `scope=all`의 검색어는 백엔드에서 강릉 영역으로 제한한다.

응답 예시는 다음과 같다.

```json
{
  "scope": "all",
  "category": "cafe",
  "page": 0,
  "size": 15,
  "isEnd": false,
  "places": [
    {
      "externalPlaceId": "12345",
      "name": "카페 예시",
      "category": "cafe",
      "categoryName": "음식점 > 카페",
      "address": "강원특별자치도 강릉시 ...",
      "roadAddress": "강원특별자치도 강릉시 ...",
      "phone": "033-000-0000",
      "placeUrl": "https://place.map.kakao.com/12345",
      "latitude": 37.77,
      "longitude": 128.94,
      "distanceMeters": null,
      "nearestStopId": null,
      "nearestStopName": null
    }
  ]
}
```

`nearby` 응답에서는 기존처럼 `distanceMeters`, `nearestStopId`, `nearestStopName`, 추천 점수·이유를 채운다. `all` 응답에서는 거리와 기준 관광지를 채우지 않는다. `isEnd`는 카카오 결과의 마지막 페이지 여부를 나타낸다.

### 오류

- 허용하지 않는 카테고리·범위·정렬·페이지는 400 응답으로 거부한다.
- 정상적인 검색 결과 없음은 200과 빈 `places`로 반환한다.
- 카카오 키 누락·권한 오류·쿼터 초과·서버 오류는 기존 오류 코드와 상태 처리를 유지한다.
- `강릉 전체` 검색 실패를 빈 결과로 위장하지 않는다.

## 데이터 흐름

### 주변 추천

```text
코스 관광지 최대 3개
→ 각 관광지 반경 2km 카테고리 검색
→ 카카오 ID 중복 제거
→ 추천순 또는 거리순 정렬
→ 거리·추천 이유와 함께 반환
```

### 강릉 전체

```text
카테고리 + 선택적 검색어
→ 강릉 bounding box 카카오 검색
→ page 단위 결과 반환
→ 프론트가 목록·지도 노드 표시
→ 사용자가 선택하면 기존 미리보기·추가 흐름 사용
```

## 성능과 쿼터

- 모드·카테고리·검색어 변경 시 필요한 첫 페이지만 요청한다.
- 추가 페이지는 스크롤 또는 더보기 동작에서 요청한다.
- React Query 캐시 키에 모든 검색 조건을 포함하고, 짧은 시간의 동일 요청은 캐시를 사용한다.
- 백엔드는 한 요청에서 카카오 최대 페이지를 모두 순회하지 않는다.
- 카카오 API가 지원하는 `rect`와 페이지 제한을 넘지 않도록 `size`를 15 이하로 제한한다.

## 테스트 전략

### 백엔드

- 카카오 Local client가 `rect`, keyword, category, page, size를 올바르게 전송하는지 검증한다.
- `nearby`가 기존 관광지 기준·2km·추천순·거리순을 유지하는지 검증한다.
- `all`이 기준 관광지와 거리값 없이 강릉 전체 검색을 수행하는지 검증한다.
- `all`의 검색어 전달, 페이지·`isEnd` 매핑, 카카오 ID 중복 제거를 검증한다.
- 허용 카테고리에서 `attraction`이 제외되는지 검증한다.
- 기존 외부 장소 추가·삭제·순서 변경 테스트를 모두 통과시킨다.

### 프론트엔드

- 모드 전환에 따라 기준 관광지·정렬·검색창의 표시 상태가 바뀌는지 검증한다.
- 카테고리 버튼이 카페·음식점·문화시설만 렌더링하는지 검증한다.
- 모드·카테고리·검색어·페이지별 API query key와 매핑을 검증한다.
- 전체 검색 카드에서 거리·기준 관광지 문구가 숨겨지는지 검증한다.
- 전체 검색 결과가 지도 노드로 전달되고 기존 추가·미리보기 동작을 유지하는지 검증한다.
- 기존 추천순·거리순과 코스 결과 회귀 테스트를 통과시킨다.

## 범위 밖

- `강릉 대표`의 리뷰 수·별점 기반 목록 수집과 하드코딩은 이번 작업에 포함하지 않는다.
- 카카오맵 웹페이지를 크롤링해 리뷰·별점을 추출하지 않는다.
- 관광공사 연관관광지·중심관광지 API를 이번 검색 모드에 직접 결합하지 않는다.
- 강릉 전체 장소를 우리 전역 `Place` 카탈로그나 장기 DB 데이터로 저장하지 않는다.
